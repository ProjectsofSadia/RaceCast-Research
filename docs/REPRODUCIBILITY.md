# Reproducibility

This document describes the environment, data organization, dependencies, and execution procedure used to reproduce the RaceCast cross-circuit Formula 1 telemetry analysis.

The repository contains the analysis pipeline, research outputs, figures, and supporting documentation. Raw Formula 1 telemetry is not redistributed.

---

## 1. Environment

The analysis was developed and executed using Python.

### Recommended environment

- Python 3.12
- pip
- Git
- Windows, macOS, or Linux

Python 3.12 is recommended for compatibility with the scientific-computing and explainability packages used by the project.

---

## 2. Clone the Repository

Clone the public RaceCast research repository:

```bash
git clone https://github.com/ProjectsofSadia/RaceCast-Research.git
cd RaceCast-Research
```

source .venv/bin/activate

## 5. Data Source

RaceCast uses publicly accessible Formula 1 timing and telemetry data obtained through FastF1.

The study analyzes qualifying telemetry from five events in the 2024 Formula 1 season:

| Event | Session |
|---|---|
| Bahrain | Qualifying |
| Monaco | Qualifying |
| Monza | Qualifying |
| Silverstone | Qualifying |
| Suzuka | Qualifying |

The processed research dataset contains:

- 5 circuits
- 372 same-driver lap comparisons
- 2,487 segment-level observations
- 21 drivers represented

Raw telemetry and FastF1 cache files are intentionally excluded from this repository.

Users reproducing the study should retrieve the underlying telemetry through FastF1 and comply with the applicable data-source terms.

## 7. Configure the Raw Data Path

The public analysis script is located at:

```text
src/run_full_analysis.py
```

The script expects the processed RaceCast telemetry dataset to be available locally.

If your local directory structure differs from the original research environment, update the raw-data path configuration near the beginning of:

```text
src/run_full_analysis.py
```

so that it points to your local:

```text
racecast_research_starter/data/raw/
```

directory.

No absolute path from the original development machine should be required once this configuration is adjusted.

---

## 8. Run the Analysis

From the root of the repository, execute:

```bash
python src/run_full_analysis.py
```

The pipeline performs the complete research analysis.

The major stages are:

1. Load processed qualifying telemetry.
2. Construct same-driver comparison/reference lap pairs.
3. Resample telemetry in the distance domain.
4. Detect corner-centered analysis segments.
5. Engineer segment-level telemetry features.
6. Calculate segment and cumulative time deltas.
7. Generate descriptive statistics and correlation analysis.
8. Train regression models.
9. Perform leave-one-circuit-out evaluation.
10. Run feature-group ablation.
11. Calculate permutation feature importance.
12. Generate SHAP explainability outputs where supported.
13. Produce paper-ready tables, figures, and summary results.

---

## 9. Reference-Lap Construction

For each driver within each circuit, the fastest selected valid qualifying lap is used as the reference.

Other selected laps from the same driver are compared against that reference.

This design reduces between-driver variation and allows the analysis to focus on within-driver telemetry differences associated with changes in segment traversal time.

---

## 10. Distance-Domain Alignment

Telemetry traces are aligned by circuit distance rather than timestamp.

The telemetry is resampled to a:

```text
5 m distance grid
```

This allows comparison and reference laps to be evaluated at approximately equivalent physical positions around a circuit.

---

## 11. Circuit Segmentation

Corner-centered segments are generated using local minima in a smoothed reference-lap speed trace.

These automatically derived segments provide a consistent computational framework for decomposing lap-time differences.

They should not be interpreted as official circuit corner definitions.

---

## 12. Target Variable

The primary target is:

```text
target_segment_time_delta_s
```

Conceptually:

```text
segment time delta =
comparison segment traversal time
-
reference segment traversal time
```

Positive values indicate time lost relative to the reference lap.

Negative values indicate time gained.

The objective is segment-level performance decomposition rather than race-result prediction.

---

## 13. Feature Engineering

The research dataset contains telemetry-derived features representing several aspects of lap execution.

### Speed-related features

- Entry-speed delta
- Minimum-speed delta
- Mean-speed delta
- Exit-speed delta
- Exit-acceleration proxy

### Braking features

- Brake-fraction delta
- Relative brake-start delta
- Brake-zone-length delta

### Throttle features

- Mean-throttle delta
- Full-throttle-fraction delta
- Relative throttle-reapplication delta

### Powertrain and vehicle-state features

- Mean-RPM delta
- Mean-gear delta
- Gear-change delta
- DRS-fraction delta

### Segment context

- Segment length
- Reference segment traversal time

## 14. Machine-Learning Models

The research evaluates three supervised regression approaches:

- Linear Regression
- Random Forest
- Gradient Boosting

The models estimate segment-level time delta from the engineered telemetry features.

The objective is not simply to determine which algorithm achieves the lowest training error, but to test whether learned telemetry relationships transfer to circuits excluded from model training.

---

## 15. Leave-One-Circuit-Out Validation

The primary evaluation strategy is leave-one-circuit-out cross-validation.

For each evaluation fold:

```text
Training data: 4 circuits
Testing data:  1 unseen circuit
```

The procedure is repeated until each of the five circuits has served as the held-out test circuit.

This avoids randomly mixing telemetry segments from the same circuits between training and testing and provides a stronger test of cross-circuit generalization.

---

## 16. Evaluation Metrics

Model performance is evaluated using:

- Mean Absolute Error (MAE)
- Root Mean Squared Error (RMSE)
- R²

Additional analysis includes:

- Spearman rank correlation
- Feature-group ablation
- Permutation importance
- SHAP feature attribution
- Circuit-level error analysis
- Analytical baseline comparison

---

## 17. Analytical Baseline

The research also evaluates a non-learned analytical reconstruction based on the relationship between:

- Segment distance
- Reference segment traversal time
- Mean-speed difference

For segment length \(L\) and reference traversal time \(t_{ref}\):

```text
v_ref = L / t_ref
```

The comparison speed is reconstructed using the observed mean-speed difference:

```text
v_cmp = v_ref + Δv
```

and the estimated comparison traversal time becomes:

```text
t_cmp_hat = L / v_cmp
```

The reconstructed segment-time delta is therefore:

```text
delta_t_hat = t_cmp_hat - t_ref
```

This baseline is important because mean speed and traversal time are mathematically coupled.

The analytical reconstruction outperformed the strongest evaluated learned model in the final comparative analysis, demonstrating why domain-informed baselines are necessary before attributing predictive performance to machine learning.

## 20. Computational Considerations

SHAP analysis can be substantially slower than the other stages of the pipeline.

Depending on hardware and SHAP configuration, explainability computation may require significantly more time than model fitting or LOCO evaluation.

This does not indicate that the analysis has stalled.

For faster development runs, SHAP sample sizes can be reduced, provided that any resulting figures or statistics are not presented as the final research outputs without being regenerated under the documented research configuration.

## 21. Reproducibility Limitations

Several limitations should be considered when reproducing or extending the study.

### Public telemetry

The project uses publicly accessible telemetry rather than proprietary team telemetry.

Professional motorsport datasets may contain substantially richer channels, higher sampling rates, additional vehicle-state information, and more detailed braking measurements.

### Target-feature coupling

Mean speed is mathematically related to segment traversal time.

Consequently, strong predictive performance from speed-derived variables should not automatically be interpreted as evidence that a machine-learning model has discovered an independent physical mechanism.

### Circuit segmentation

Segments are derived from reference telemetry rather than from a fixed canonical engineering track map.

A segment with the same numerical index is therefore not guaranteed to represent an identical type of corner across drivers or circuits.

### Unobserved variables

The public dataset does not fully control for:

- Fuel load
- Detailed vehicle setup
- Tire condition
- Tire temperature
- Track evolution
- Wind
- Traffic effects
- Component state
- Driver-specific objectives

These factors can influence telemetry and lap performance.

### Causality

The analysis identifies predictive relationships and reconstructs performance differences.

It does not establish that changing an individual telemetry feature would causally produce the corresponding lap-time change.
